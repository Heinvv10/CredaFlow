## Purpose
Statement → transactions, one `StatementAnalysis` per (bytes, `PARSER_VERSION`),
for `lib/credit-checks/`; categories and insights on read. Pipeline: `analyse.ts`.

## Critical Rules
- **The balance check is the oracle.** opening + Σ amounts = closing (±1c), and
  each printed running balance = previous + amount (`balance-check.ts`). A
  reader change is only right if bank-produced corpus files still PASS.
- **Text readers** (`TEXT_READERS`): Capitec, FNB, Nedbank, ABSA (two layouts),
  Standard Bank, Discovery. Standard Bank and Discovery are **limited evidence**
  (6–9 corpus files) until 20+ have been seen. Banks the header (above the first row)
  names are tried first, then any other the text names (`detectBanks`). Other banks,
  scans and photos go to the vision reader (`vlm-reader.ts`).
- **What arithmetic cannot check goes to a person** (MANUAL_REVIEW): a derived opening
  (ABSA Transaction History, Discovery: FIRST_ROW_UNVERIFIED) or closing (Discovery:
  LAST_ROW_UNVERIFIED), rows printed without a balance (ABSA eStatement: ROWS_UNCHECKED).
  Other closings are printed (Standard Bank: opening + summary totals). A row lacking a
  balance its bank prints on every row is not read; with no closing, balances still check.
- **A vision read is never tamper evidence**: its balance FAIL is MANUAL_REVIEW/UNVERIFIED_READ, never BALANCE_MISMATCH (a misread and a forgery look alike).
- **Never call the vision reader or the label model inside a staff request** (`persist.ts` `allowVlm: false`; labels only in its background queue).
- **Model labels** (`model-labels.ts`, off): `VOTE_RUNS` runs; living needs all, others a majority;
  a refused or garbage batch and a key left out of the answer abstain (an echoed invalid value votes
  UNCATEGORISED); `NEVER_APPLIED` (credit, gambling) never applies; another prompt version's stored labels are ignored.
- **Bump `PARSER_VERSION`** when a reader's output changes for the same bytes, and
  `CATEGORISER_VERSION` when `categorise.ts`/`merchants.ts` do (checks' lists stay in policy.ts).
  Categories are computed on read; the one stored input is the model's label per masked debit key no
  rule categorises (`model-labels.ts`; the read's own row, `modelCategories`), shown model-assigned;
  off (`MODEL_LABELS`) until a run passes the §6.4 gate (2026-10-15: 67.1–90.3%).
- **FNB marks only credits** ("Cr"); unmarked is a debit / overdrawn. A row
  printing an amount that moves no money is `nonPosting` only when the balance
  confirms it: FNB "EDO Collection Attempt", ABSA "( PENDING )"/"DECLINED FEE".
  Nedbank's Fees column, like FNB's accrued charges, is not the row's amount.
  Proportional-font banks (FNB, Nedbank, ABSA eStatement, Discovery) are read
  from word boxes (`pdftotext -bbox`, `word-table.ts`), not `-layout` columns.
- **Intake decryption rewrites the file** (`lib/documents/pdf-decrypt.ts`): the upload
  route records the original's revision count on DOCUMENT_DECRYPTED_AT_INTAKE for `persist.ts`.
- **A failed read is persisted** UNREADABLE (READ_FAILED), never thrown; re-extract retries it (`retryFailed`); missing PDF tools: pending.
- **Hostile-file bounds:** poppler async, pdfinfo before any text pass, text only up to
  `TEXT_MAX_PAGES`, lines over 400 chars or 200 words skipped, amounts > `MAX_CENTS` refused,
  bad periods dropped, duplicate pdfinfo fields distrusted (METADATA_AMBIGUOUS), pdfinfo fields parsed
  with `[ \t]*` (not `\s*`), one vision read (or label run) per process.

## Corpus (real client data)
- Off-repo at `STATEMENT_CORPUS_DIR`; runner in `accuracy/` (README there). Never commit,
  print or log names, ID/account numbers or transaction text; only the local `VLM_API_URL` model sees
  it (`getVlmConfig` refuses a hosted one while a corpus is set), only outside 08:00–17:00 SAST on weekdays (shared model).
- Inspect only via masked shapes (a/9), counts or metadata: `scripts/statement-{layout-shapes,
  read-diagnostics,tamper-review}.ts`; a shape "label" must recur on 5+ accounts. Readable exception:
  masked debit merchant keys on 3+ accounts (`scripts/statement-merchant-keys.ts`, off-repo).
- `fixtures/`: synthetic PDFs per text-read bank + doctored variants ("T TESTER").
