# Module: decisioning

## Purpose
A lender's own rules (knock-out, refer, limit cap) and scorecard (points per
bin -> score -> grade band) decide approve / decline / refer with a reason
code, replayable on history, with a challenger. Changes arrive only through
`lib/maker-checker/` (kinds `DECISION_RULE_SET`, `DECISION_ENGINE_CONFIG`).
Default OFF per lender (`DecisionEngineConfig`, no row = off).

## The contract A5 / A6 read: the risk grade
`LoanApplication.riskGrade` (a label the lender chose, null = not graded),
`riskScore`, `riskGradedAt`, set whenever the engine runs in SHADOW or LIVE
and a scorecard applies. `getRiskGrade(db, tenantId, applicationId)`
(`risk-grade.ts`) adds the band's `pricingTier` (opaque label to price by) and
`rank` (0 = best band). Compare grades by `rank`, never by string order.

## Critical Rules
- **An approval goes through the staff path.** `approveThroughStaffPath`
  calls `decideApplication` (`app/api/applications/[id]/decide/`) as the
  lender's delegate user, so KYC, bureau, affordability, screening, open credit
  checks, reckless-lending and NCA gates all run. A refusal becomes a REFER
  (`HARD_GATE_*`), never an override. Do not add a second approval writer.
- **Decline and refer are the engine's own writes**: system actor, decision log
  record (decline flagged `s71ReviewRequired`), approved client wording from
  `DECLINE_CLIENT_REASONS`. No rule text ever reaches the client.
- **Facts are indicative** (`facts.ts`, `load-facts.ts`); the staff path's gates
  stay authoritative. A missing fact matches no comparison (only `isNull`).
- **Rules are data**: every stored set is re-validated (`validate-*.ts`)
  before it runs; a set that fails is skipped, staff decide.
- **A cap never trims the amount**: above it the verdict is REFER.
- **Only approved versions run**: DB trigger on `DecisionRuleSetVersion`;
  versions are immutable. Champion = highest effective, non-challenger-only
  version (`select-version.ts`); challenger share is a stable hash.
- **Simulation is read-only** (`simulate.ts`); keep it so.
- `AutoDecisionRun` is append-only; SHADOW rows are `NOT_ACTED`.
- Trigger: after the review route's bureau step (`runAutoDecisionSafely`,
  never fails the review) or `POST /api/applications/[id]/auto-decision`.

## Tests
Pure units beside each file. `RUN_DECISIONING_IT=1`: `auto-decision.integration.test.ts`
(real gates under RLS, hard-gate refusal, decline, refer, shadow, challenger,
