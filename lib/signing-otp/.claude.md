# Module: signing-otp
<!-- Keep under 50 lines - reference, don't duplicate -->

## Purpose
The one-time code a borrower verifies before signing the credit agreement,
the debit mandate or any other `ClientDocument`. Request → deliver (the one
send pipeline) → verify → spent inside the signing transaction.

## Critical Rules
- **Never SMS.** Email, or WhatsApp only when the lender runs WhatsApp Cloud.
  The `SigningOtpChallenge_channel_check` CHECK refuses anything else.
- **The code is never stored, logged or audited.** `codeHash` is an HMAC keyed
  with AUTH_SECRET and bound to the challenge id; message bodies are
  `redactStoredBody` and carry an unstored `requestRef` so the Message
  fingerprint cannot be searched for the code.
- **A code signs exactly one thing.** Bound to client + purpose + subjectId +
  the SHA-256 of the bytes shown. Each sign route re-states the binding in the
  consuming `updateMany` (`consumeSigningOtp`) inside its own transaction.
- **A consumed challenge is signature evidence.** The `guardSigningOtpChallenge`
  trigger freezes it (no update, no delete); its fields are also copied into
  the signing audit row as `signingOtp`.
- **A CLIENT session is always portal signing**, whatever `method` it sends —
  it cannot claim the branch exemption.
- **No NCA wording changes.** The rendered agreement/mandate do not mention the
  OTP; adding that needs the lender's legal sign-off first.
