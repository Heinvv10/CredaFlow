# Integration suites known to fail, excluded from the gate. Every suite not
# listed here must pass.
#
# Run sequentially (--no-file-parallelism): every suite shares one database,
# and a parallel run reports contamination as breakage.
#
# This is a debt register, not a permission slip. The list may only shrink, and
# both directions are enforced:
#   - a suite listed here that starts passing fails the job
#     (scripts/run-integration-tests.sh), forcing the line out and the suite in;
#   - a PR that ADDS a line fails the job (the "Baseline may only shrink" step
#     in .github/workflows/integration-tests.yml), so a suite a PR broke cannot
#     be exempted by the same PR. The re-check EXPECTS baselined suites to fail,
#     so without that step a freshly broken suite would look like old debt.
#
# The usual cause: a migration added or tightened a constraint and the suite's
# fixture was never updated, so the scenario cannot reach the state it exists
# to test. Check LoanApplication_repayment_method_lifecycle first on any
# check-constraint violation on LoanApplication: it requires a repaymentMethod
# from APPROVED onward, and a fixture that creates an application already
# APPROVED needs it on the create.
#
# Both suites below need a fixture for a fully countersigned, disbursable
# PASQ v3 application: approval and disbursement now require one.
#
# A green suite here exercises the `guard_*_update` triggers, not necessarily
# the matching `require_*_on_insert` ones: disabling those may change nothing.
# Do not read a passing suite as proof that a whole trigger family is covered.
