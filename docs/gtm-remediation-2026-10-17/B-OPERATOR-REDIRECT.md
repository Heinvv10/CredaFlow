# G06-U — operator redirects preserve the configured console origin

Base `aeacfc065b9b8234261c2158dd98271938671ad7`; isolated branch `fix/gtm-operator-redirect-20261017`, worktree `/home/hein/Workspace/CredaFlow-gtm-b-operator`. Writable paths: operator-host helper/test and this record. F15 legal proposal remains untouched in its separate worktree.

The actual private candidate invited an operator successfully, but its mandatory enrolment redirect changed operator.localhost to localhost. Auth.js canonicalises the request URL to NEXTAUTH_URL, which is the staff origin; the console gate had constructed four redirects against that URL even though proxy.ts had validated the incoming operator Host. The host-only session cookie then correctly did not accompany the off-host navigation. Unsetting NEXTAUTH_URL is not a fix: normal staff reset and operator invitation generation need that configuration.

All four console redirects (root to home, authenticated login to home, anonymous page to login, held operator to enrolment) now use the existing requireOperatorBaseUrl helper when NEXTAUTH_URL is set. This keeps the configured canonical scheme/port and operator hostname. For previously supported unset configuration, the request scheme/port remain but the hostname is replaced with configured operatorAppHost. Redirect destinations never come from raw Host, Forwarded, X-Forwarded-Host, Origin or callback URL input. Existing authentication, mandatory TOTP, off-host refusal, support read-only, CSRF and JSON gates are unchanged. Invalid configured canonical URLs retain the deployment helper's explicit refusal.

Fail first: four real proxy-entry regressions constructed NextRequest with a staff request URL plus an operator Host and poisoned forwarded/origin headers. All four returned the staff origin (4 failures /31 existing passes), retained privately `/tmp/gtm-b-operator-failfirst.log`. After the fix all36 proxy tests pass, including same-origin scheme/port, callback path and unset-config fallback. Command: `npx vitest run lib/proxy/operator-host.test.ts --maxWorkers=2`. Changed-file ESLint and `git diff --check` pass. No DB/schema/migration or provider effects.

Browser acceptance remains required on the rebuilt exact candidate with NEXTAUTH_URL kept configured: freshly invited operator sets password, replay is refused, password login stays on operator host at mandatory enrolment, enrolment succeeds, next-code verified login reaches console, and support-role administration remains forbidden. Also check root/authenticated-login/anonymous redirects stay on operator host. No prior failed browser run establishes this fix works in a new image.
