## Finding, scope and proposed representation

Current portal held five checkbox booleans only in component state; sign request/audit did not carry an individual declaration set. The original stored credit agreement's boxes were blank. A signature alone does not establish which statements were accepted. The new candidate shares the five EXACT previously displayed portal statements as version `portal-agreement-declarations-v1`. It deliberately preserves "read and understood this Pre-Agreement Statement and Quotation"; the printed document's PASQ-received declaration differs. The certificate quotes what the portal actually displayed rather than silently mapping that to a printed checkbox.

New portal signing requires explicit version + SHA-256 of the exact shared declaration text set + all five exact IDs, after each displayed checkbox is accepted. The server captures a new append-only acceptance record inside the guarded signature transaction. The record binds tenant/application/client/signer/method/time to exact agreement, PASQ and signature SHA-256 values. A composite tenant/application/client FK and PostgreSQL INSERT guard enforce those bindings; exact version/ID set is CHECK-constrained; the server recomputes the actual shared text set and refuses same-version wording drift; UPDATE/DELETE are refused. Uniqueness is per ceremony, preserving evidence for a later distinct signing. No existing record or checkbox is backfilled.

Countersigning reads the exact current ceremony record. Present inconsistent evidence refuses execution. Verified evidence appends an electronic acceptance record to the exact stored unsigned agreement after existing signature stamping. The certificate quotes each accepted portal statement and records its version, record/client/application IDs, timestamp, declaration-set hash and document/signature hashes. Original pages/printed boxes are preserved. Old/raw-SQL signatures with no individual acceptance evidence retain their existing executed artifact and receive no certificate. Branch/returned-paper behavior is preserved; no portal assertions are inferred for it. Audit JSON is supplementary and is not trusted as the immutable source.
