## §3 A — IsaFlow connection + push (spec WP-B, §2.4–2.5)

**Connection.** `IsaFlowConnection`, one per tenant:
- Fields:
  - `status` CONNECTED | NEEDS_RECONNECT | DISCONNECTED;
  - `baseUrl`;
  - `tokenSealed`;
  - `tokenKind`;
  - `isaflowCompanyId`, `isaflowCompanyName`;
  - `connectedById`, `connectedWithTotp`, `connectedAt`;
  - `lastVerifiedAt`;
  - `disconnectedAt`.
- A DB guard: CONNECTED needs `connectedWithTotp` and a SUPER_ADMIN of the same tenant.
- `baseUrl`: https only and allow-listed by env `ISAFLOW_ALLOWED_ORIGINS`, through the SSRF helpers. Loopback http is allowed only under test.
- On connect, prove the scopes: call `company_profile` and `list_gl_accounts`.
- Route `app/api/integrations/isaflow/route.ts`:
  - GET (ADMIN): status, never the token.
  - connect / verify / disconnect: via `superAdminPolicyWrite`.
  - Every action is audited.

**Push.** `AccountingIsaFlowPush`, one per CLOSED batch:
- The guard trigger copies Xero's, and makes `requestSha256`, `idempotencyKey` and `isaflowCompanyId` immutable and `isaflowJournalId` write-once.
- `pushBatchToIsaFlow`:
  1. Load the batch digest-checked.
  2. Refuse any line whose role has no stored mapping matching its code.
  3. Validate every code exists and is active via `list_gl_accounts`, mapping codes to UUIDs. Return 422 listing the bad codes, with **nothing claimed**.
  4. Build the args once: net per account, rands to 2 dp, dated period end.
  5. Claim SENDING.
  6. Send with the stable key.
  7. Record the outcome as PUSHED, FAILED or NEEDS_REVIEW.
- **Read-back before any retry:** `list_journals` with draft status, the date and the memo tag, plus totals.
  - If found → PUSHED.
  - If not → resend the stored request byte-for-byte with the same key.
- **Stale SENDING** becomes NEEDS_REVIEW after 10 minutes, with a manual resolve.
- Push route `app/api/accounting/batches/[id]/isaflow/route.ts` (push / check / resolve): ADMIN, with **TOTP always required**.

**UI:**
- A connection card on the settings integrations page.
- Push button and status in the accounting export panel.
- Tokens use the `--cf-*` design tokens; light/dark; 390 px.

**Fake IsaFlow** (spec §2.5):
- `node:http` JSON-RPC server: Bearer PAT and scopes, `company_profile`, paged `list_gl_accounts` with inactive accounts, `create_draft_journal` with balance/ownership checks and key+argsHash replay, `list_journals`.
- Knobs: `failNext`, `commitThenDrop`, `deleteDraft`, `calls[]`.
- A unit test pins its replies to the IsaFlow file:line contract.

**Tests (TDD):**
- Client unit tests: error kinds, rands formatting, cursor paging.
- Route tests: ADMIN without TOTP gets 403; SUPER_ADMIN without TOTP gets 403; a role demoted mid-write is refused.
- IT:
  - two pushes give one draft;
  - commitThenDrop → NEEDS_REVIEW → check finds it on read-back → PUSHED, with no second create;
  - a deleted draft is resent with the same key;
  - an unmapped role is refused before any HTTP;
  - an unknown or inactive code is refused before claim.
- Guard-trigger ITs, mutation-verified.
- Cross-tenant ids give 404.
- The token never appears in GET responses or audit rows.
